# How MeshCards Generates Anki (.apkg) Files

MeshCards uses a multi-stage pipeline to transform raw documents into high-quality Anki flashcards. This process is optimized for educational quality and memory retention.

## 1. Input Processing & Text Extraction
When you upload a file (PDF, TXT, etc.) or paste text, the backend first extracts the raw content:
- **PDFs**: Uses `pypdf` to extract text from each page.
- **Text**: Standardizes encoding to UTF-8.
- **Multimodal**: For images, the system uses vision-capable models (like Gemini 2.0 Flash or Llama 3.2 Vision) to "read" the visual information.

## 2. Smart Chunking & Data Optimization
The raw text is often too large for a single AI prompt. We use a custom `Chunker` to:
- **Semantic Extraction**: Prioritizes definitions, headings, and bullet points.
- **Context Retention**: Splits text at paragraph or sentence boundaries to ensure the AI doesn't lose the "meaning" of a concept.
- **Fallbacks**: If a document is unstructured, it takes introductory and concluding sections to capture the core mission of the text.

## 3. AI Flashcard Generation
The optimized text is sent to the "Intelligence Engine" (Gemini or Rare Models). The AI is prompted to:
- Generate content in **JSON format**.
- Create distinct Question/Answer pairs or Cloze Deletions.
- Use **LaTeX** for mathematical formulas (e.g., `\( E=mc^2 \)`).
- Assign relevant **tags** for better organization in Anki.

## 4. Deck Construction
We use the `genanki` library to assemble the final package:
- **Templates**: Custom HTML/CSS templates are applied to ensure cards look great on Anki Desktop and Mobile.
- **MathJax**: A hidden `{{MathJax}}` tag is added to the template so your formulas render natively without add-ons.
- **Unique IDs**: Every card and deck is assigned a cryptographically random 10-digit ID. This prevents "Deck Collisions" when you import multiple decks into your Anki collection.

## 5. Storage & Delivery
- The deck is saved as a `.apkg` file in a temporary directory.
- In **Production**, the file is uploaded to **Supabase Storage** and a signed download link is generated.
- In **Development**, the file is served directly from the backend file system.
